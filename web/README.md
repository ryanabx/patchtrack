# patchtrack in the browser

A Preact app over `patchtrack bridge` (or `patchtrack serve`): the store
lives on the machine the bridge runs on, which derives every answer from
it, syncs it on its own, sends mail and runs b4. The app keeps nothing but
the bridge's address and token. See ../ARCHITECTURE.md.

```sh
npm ci
npm run dev       # http://localhost:5173
npm run build     # dist/: any static host, e.g. GitHub Pages
npm test
npm run types     # after changing the model: regenerates src/core from the Rust types
```

| path | what |
|---|---|
| `src/core/` | the model's TypeScript types, generated by ts-rs from patchtrack-core: the contract |
| `src/store.ts` | the typed client of the bridge's API (crates/cli/src/api.rs) |
| `src/protocol.ts` | the bridge's answers that are not the core's model |
| `src/views/` | the series list (everyone's, followed, or yours), a series (conversation, commits, files changed, sidebar), notifications (unread, needs you), people, branches, drafts, following, adding mail, settings |
| `src/lib/format.ts` | presentation without the DOM: dates, states, evidence, quotes, diffs (tested) |
| `src/lib/bridge.ts`, `drafts.ts`, `branches.ts`, `diff.ts` | pairing; handing a draft to a mail client; which b4 branch posted a series; a patch's files, hunks and line numbers, and archive URLs (tested) |

Mail is text, never markup: nothing uses `dangerouslySetInnerHTML`, and the
built page's Content-Security-Policy admits only the site's own code.

`public/sw.js` is not a service worker the app registers: it replaces the
one an earlier version installed, and unregisters itself.

## In a real browser

`e2e/run.py` drives the built app in headless Firefox over Marionette
(Python's standard library only; no WebDriver or Selenium), against
`patchtrack bridge` and `serve` syncing from a fake archive. Build first:

```sh
npm run build && cargo build -p patchtrack
python3 e2e/run.py
```

## From the development server

`patchtrack bridge` serves only the origins it is told of: by default the
published app's. With `npm run dev` on http://localhost:5173, start it as

```sh
patchtrack bridge --app http://localhost:5173/
```

and open the link it prints. A bridge started for another origin refuses
the page; the page cannot see why (the refusal has no CORS headers), so it
checks whether the bridge is reachable at all and says which it is, and the
bridge's own output names the option that would let the page in.
